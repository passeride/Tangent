# ADR-0029: Sequential Play with a shared transport barrier

- Status: Accepted
- Decision date: 2026-10-26
- Delivery: Implemented; physical instrument/latency review pending
- Related: [ADR-0020](0020-variable-playback-speed.md), [ADR-0021](0021-passage-practice-and-comparable-context.md), [brief](../design/sequential-play.md)

## Context

The owner requested an optional first-pass mode that pauses at each note until
correct input, with adjustable tolerance. Audio/MIDI lookahead must obey the same
stop as notation, without treating automatic playback as an answer. Chords,
repeated pitches, manual pause and loop boundaries require explicit semantics.

## Decision

`tangent-core::guided` owns onset groups, accepted attacks and the next source-time
barrier, independent of Bevy or devices. Exact simultaneous onsets form a chord;
unisons are deduplicated. Existing part/passage selection and percussion exclusion
apply. Correct MIDI pitch and octave are required. Each chord key needs a fresh
attack and all required keys must be held together before advancement. Players can
assemble a chord slowly while stopped. Repeated keys require release and a new
attack; keys held before the acceptance window do not answer a later gate.

Sequential is off by default and enabled through Pause or Settings → Practice.
Early input cycles through 0/100/250/500 ms, default 250. This is a wall-time early
window, converted through playback speed, not pitch tolerance or a late deadline.
Late input waits indefinitely. Manual pause accepts no progress. Selected loop
repeats rebuild the full gate sequence, including after seeking into the loop.
Restart, seek, selection and mode/config changes reset gate state.

`Transport::advance_until` clamps at the pending onset before loop/end handling.
The scene keeps user play intent distinct from automatic waiting. Both platform
adapters receive an exclusive `gate_us` scheduling cap and effective playing
state. They must never schedule the pending attack through lookahead. At a gate,
reconstructed output includes boundary releases/controllers but excludes boundary
attacks. Guided reanchors preserve manually played voices; native/web MIDI keep
song and live key identities separate on the manual channel. Hardware MIDI input
is still not echoed. No platform adapter owns target-matching rules.

`SongContext.guided` is optional with a validated `early_ms` (0–500). Absence keeps
old records compatible. Normal, sequential and different-window attempts compare
only within identical contexts; retry restores the recorded mode/window. Local
preferences remember the mode/window independently. SQLite schema versions and
tables are unchanged; Rust and JS validate the new optional context. Song points
remain pitch coverage; guided results explicitly describe waiting, never calibrated
timing or unaided mastery. Automatic output cannot earn coverage.

## Alternatives and consequences

A scene-only pause would let lookahead play past targets and duplicate musical
rules across native/web. Pitch-nearest matching would accept wrong octaves; a
late timeout would defeat beginner walkthroughs. A full transport rewrite is
unnecessary: the existing rate-aware clock gains one optional barrier.

Existing speed and passage contracts are extended, not replaced. Pedal-aware
input, expressive arpeggio grouping across unequal onsets, latency calibration
and physical hand inference remain outside this slice. Sustained song envelopes
can rearticulate on resynchronization, consistent with existing seek behavior.

## Validation

Core tests cover exact gates, chords/held keys, wrong input, early wall-time at
changed speeds, manual pause, repeated attacks, selected parts/unisons, loops,
mid-loop seeks and comparable contexts. Native MIDI snapshot/live-preservation
and preference tests run against actual source modules; native and WASM Clippy
check the integrations. Browser tests use the real Bevy WASM with simulated MIDI,
verify no future/ended backing attacks at gates, live voice preservation, a scored
five-target attempt, retry, persistent tolerance/history and responsive settings.
Screenshots are generated by `capture.mjs` with `TANGENT_CAPTURE_GUIDED=1`.
Physical GPU/audio/MIDI timing still requires a real instrument.

Delivery checks: all 122 workspace Rust tests, native/workspace and WASM
warnings-denied Clippy, formatting, release WASM build, Sequential/tempo/passage/
MIDI-practice/Five Finger Flow browser regressions, packaged `/Tangent/` audio
smoke and native debug executable self-test pass. Physical instrument tests remain
pending.
